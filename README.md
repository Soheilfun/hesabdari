# حساب‌یار — نسخه ۱.۸.۲ بتا

نرم‌افزار حسابداری مغازه ابزارفروشی — وب‌اپی که روی گوشی و کامپیوتر کار می‌کند، داده را روی Cloudflare D1 نگه می‌دارد، بی‌اینترنت هم می‌نویسد و یک دستیار هوشمند دارد که می‌تواند فاکتور بزند، کالا ثبت کند و گزارش بدهد.

- تقویم **شمسی**، اعداد فارسی، واحد پول **تومان**، چیدمان راست‌به‌چپ
- **داده روی سرور** (D1)؛ حافظه مرورگر فقط کش آفلاین است
- **کار آفلاین + سینک خودکار**؛ با قطع اینترنت ثبت‌ها در صف می‌مانند
- نصب روی گوشی به شکل **PWA**، حالت تیره، بهینه‌سازی کامل موبایل

## تازه‌های ۱.۸.۲ بتا

- دکمهٔ «ثبت نهایی سفارش» در موبایل درست شد: کشوی سبد به «برگهٔ پایین» تبدیل شد و دکمه همیشه در دسترس است.
- فیلدها ۱۶ پیکسل شدند تا آیفون هنگام تایپ زوم نکند.
- فرم تماس دیگر با خطا یا تغییر تعداد پاک نمی‌شود؛ با کلید Enter هم سفارش ثبت می‌شود.
- سفارش بیشتر از موجودی ممکن نیست و کالای ناموجود به سبد اضافه نمی‌شود.
- سبد ذخیره‌شده با موجودی روز هماهنگ می‌شود و کالای حذف‌شده کنار می‌رود.
- دکمهٔ «دیدن صفحهٔ فروشگاه» در برنامه درست شد (در اپ نصب‌شده هم کار می‌کند).
- موجودی هرگز منفی نمی‌شود و فهرست ویترین با بازگشت به صفحه خودبه‌خود تازه می‌شود.

## تازه‌های ۱.۸.۱ بتا

- **کسر فوری موجودی با هر سفارش سایت**: به‌محض ثبت سفارش، موجودی کالا در سرور کم می‌شود و لیست کالاهای برنامه و ویترین تازه می‌شود (قابل خاموش کردن در تنظیمات).
- **اعلان لحظه‌ای**: تا برنامه باز است، با رسیدن سفارش تازه پیام نشان داده می‌شود و نشانگر منو بالا می‌رود.
- **دکمهٔ به‌روزرسانی** و همگام‌سازی خودکار هنگام باز کردن صفحهٔ سفارش‌های سایت.
- تبدیل سفارش به فاکتور دیگر موجودی را دوباره کم نمی‌کند.
- پاسخ `\/api\/shop\/catalog` دیگر کش نمی‌شود؛ مشتری همیشه قیمت و موجودی روز را می‌بیند.

## تازه‌های ۱.۸ بتا

- **ویترین عمومی فروشگاه** در آدرس `/shop.html`؛ لیست متنی کالاها با قیمت و وضعیت موجودی، مستقیم از انبار حساب‌یار (بدون نیاز به رمز).
- **سبد سفارش و فرم تماس**: مشتری کالا را انتخاب می‌کند، تعداد می‌دهد و نام و شمارهٔ تماس ثبت می‌کند؛ سبد در مرورگر ذخیره می‌ماند.
- **درگاه پرداخت نمایشی**: گزینهٔ «پرداخت اینترنتی» در صفحه دیده می‌شود اما غیرفعال است (به‌زودی).
- **صفحهٔ سفارش‌های سایت** در منوی «فروش و انبار» با نشانگر سفارش جدید، دکمهٔ تماس، تغییر وضعیت و **تبدیل به فاکتور فروش** با یک کلیک (کسر خودکار موجودی + ساخت طرف حساب).
- دو مسیر تازهٔ API: `GET /api/shop/catalog` و `POST /api/shop/order` (عمومی، با اعتبارسنجی و قیمت‌خوانی سمت سرور).

## تازه‌های ۱.۷.۲ بتا

- **تب کالاهای تمام‌شده و رو به اتمام** در صفحهٔ کالاها (همه / رو به اتمام / تمام شده).
- **فروش سریع** بدون صدور فاکتور کامل؛ از داشبورد، صفحهٔ کالاها و دکمهٔ هر ردیف کالا.
- **حذف منوی «ورود گروهی»** از نوار کناری؛ فقط دکمهٔ داخل صفحهٔ کالاها.
- **همگام‌سازی زنده** بین دو دستگاه: هر ۷ ثانیه (پس‌زمینه ۳۰ ثانیه) + هنگام برگشت به صفحه، بدون نیاز به خروج یا رفرش.
- **رفع باگ کسر موجودی**: با فاکتور فروش، موجودی کالا حتی با تطبیق نام کم می‌شود.
- **بخش پرداخت هوشمند فاکتور**: نقد ← صندوق، کارتخوان ← انتخاب دستگاه، کارت به کارت/انتقال ← حساب و شماره پیگیری، چک ← ثبت خودکار در دفتر چک‌ها، اعتباری ← ثبت خریدار (نام و تلفن) در طرف حساب‌ها.
- **بدهکار/بستانکار** در صفحهٔ طرف حساب‌ها به‌همراه جمع کل طلب و بدهی.

## تازه‌های ۱.۷.۲ بتا

- **دستیار هوشمند** با ۱۳ ابزار خواندن و ۱۵ ابزار ثبت؛ هر تغییر داده قبل از اجرا کارت تأیید نشان می‌دهد
- پشتیبانی از سرویس‌های **سازگار با OpenAI** (Mistral، 9Router، OpenRouter، AvalAI، GapGPT، لیارا) و همچنین Gemini
- **تلاش مجدد خودکار** وقتی سرور مدل شلوغ است (خطاهای ۴۲۹ و 5xx)
- **بهینه‌سازی موبایل**: بدون زوم خودکار روی فیلدها، نوار بالای چسبان، دکمه‌های ذخیره چسبیده به پایین کشو، اهداف لمسی ۴۴ پیکسلی، بدون اسکرول افقی

## ساختار پروژه

```
├─ public/                    ← فایل‌های ساکن
│  ├─ index.html              ← پوسته برنامه + صفحه ورود
│  ├─ manifest.webmanifest    ← نصب روی گوشی (PWA)
│  ├─ sw.js                   ← کش پوسته برای کار آفلاین
│  ├─ assets/app.css          ← سیستم طراحی، ریسپانسیو، موبایل، چاپ
│  └─ js/
│     ├─ core.js             ← تقویم شمسی، قالب اعداد، منطق حسابداری
│     ├─ data.js             ← کلاینت API، مخزن داده، صف آفلاین، موتور سینک
│     ├─ ui.js               ← کارت، جدول، کشو، دیالوگ، اعلان
│     ├─ agent.js            ← ابزارهای دستیار و حلقه گفت‌وگو
│     ├─ views-chat.js       ← صفحه دستیار هوشمند
│     ├─ views-sales.js      ← داشبورد، فاکتورها، کالاها، ورود گروهی
│     ├─ views-finance.js    ← مالی، چک، بودجه، اسناد، گزارش، تنطیمات
│     └─ app.js              ← ورود، مسیریابی، منو، جست‌وجو، تم
├─ src/
│  ├─ worker.js               ← نقطه ورود Worker
│  ├─ api.js                 ← ورود، سینک، خروجی، ریست
│  └─ chat.js                ← پروکسی مدل هوش مصنوعی (کلید فقط روی سرور)
├─ functions/api/[[route]].js  ← سازگاری با Cloudflare Pages
├─ schema.sql                 ← ساختار دیتابیس D1
└─ wrangler.toml
```

## راه‌اندازی

### ۱) ساخت دیتابیس

```bash
npm i -g wrangler
wrangler login
npx wrangler d1 create hesabyar
```

خروجی یک `database_id` می‌دهد؛ دقیقاً همین مقدار را در `wrangler.toml` در کلید `database_id` بگذارید.

> اگر خطای `D1 binding 'DB' references database ... [code: 10181]` گرفتید، معنیش این است که این شناسه در حساب شما وجود ندارد.

### ۲) ساخت جدول‌ها

```bash
npx wrangler d1 execute hesabyar --remote --file=./schema.sql
```

### ۳) تنطیم متغیرها

در داشبورد Cloudflare → Workers & Pages → `hesabyar` → Settings → Variables and Secrets:

| نام | نوع | توضیح |
|---|---|---|
| `APP_PASSWORD` | Secret | رمز ورود به برنامه |
| `AUTH_SECRET` | Secret | رشته تصادفی بلند برای امضای نشست |
| `AI_API_KEY` | Secret | کلید سرویس هوش مصنوعی (مثلاً Mistral) |
| `AI_MODEL` | Text | مثلاً `mistral-medium-3-5` یا `mistral-large-2512` |
| `AI_BASE_URL` | Text | اختیاری؛ پیش‌فرض `https://api.mistral.ai/v1` |

برای استفاده از Gemini به جای این‌ها فقط `GEMINI_API_KEY` (و اختیاری `GEMINI_MODEL`، پیش‌فرض `gemini-3.5-flash`) را بگذارید.

### ۴) دیپلوی

```bash
npx wrangler deploy
```

یا مخزن گیت‌هاب را به Workers Builds وصل کنید تا هر push خودکار دیپلوی شود.

## دستیار هوشمند

نمونه درخواست‌ها:

- «۱۰ عدد پیچ خودکار ۴۰ فروختم به رضایی، فاکتور بزن»
- «قیمت فروش دسته پیچ و مهره را ۱۰ درصد زیاد کن»
- «این ماه چقدر سود کردم؟»
- «چک‌های دو هفته آینده»

قاعده‌ها:

- محاسبات از خود برنامه می‌آید، نه از مدل؛ پس عدد اشتباه ساخته نمی‌شود.
- هر عملیاتی که داده را تغییر می‌دهد اول پیش‌نمایش می‌شود و با تأیید شما اجرا می‌شود.
- کلید API هرگز به مرورگر نمی‌رود؛ همه درخواست‌ها از مسیر `POST /api/chat` روی Worker می‌گذرند.
- دستیار به اینترنت نیاز دارد؛ بقیه برنامه آفلاین هم کار می‌کند.

## API

| مسیر | کاربرد |
|---|---|
| `POST /api/auth/login` | ورود با رمز مشترک و دریافت توکن (۳۰ روز) |
| `GET /api/auth/session` | بررسی اعتبار نشست |
| `GET /api/state?since=` | دریافت تغییرات از یک زمان به بعد |
| `POST /api/sync` | ارسال دسته‌ای ثبت‌ها |
| `POST /api/chat` | گفت‌وگو با مدل (نیازمند ورود) |
| `GET /api/export` | پشتیبان کامل JSON |
| `POST /api/reset` | پاک کردن همه داده‌ها با `{"confirm":"DELETE"}` |

## پشتیبان‌گیری

تنطیمات → «دانلود پشتیبان کامل» یک فایل JSON از همه داده‌ها می‌گیرد. پیشنهاد: روزی یک بار قبل از بستن مغازه.

## محدودیت‌های نسخه بتا

- دستیار در هر پیام حداکثر ۶ گام ابزار اجرا می‌کند و تاریخچه گفت‌وگو تا ۴۰ پیام نگه داشته می‌شود.
